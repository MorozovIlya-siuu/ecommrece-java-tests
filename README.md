# E-commerce Java Tests

Лабораторная работа №3 по дисциплине "Тестирование ПО".

## Ответы на вопросы

### 1. Какие события активируют пайплайн?
Пайплайн активируется событиями `push` и `pull_request` в ветки `main` или `master`.

### 2. Будет ли пайплайн запускаться при изменении только README.md?
Да, будет, так как триггер настроен на любое изменение в ветке. Чтобы избежать этого, можно добавить `paths-ignore: ['**.md']`.

### 3. Как указывается установка зависимостей?
В Java-проекте зависимости управляются через `pom.xml`. Maven автоматически скачивает их при запуске `mvn clean verify`. В `ci.yml` это делается одной командой: `mvn clean verify`.

### 4. Как настроить запрет на слияния, если тесты упали?
В настройках репозитория: Settings → Branches → Branch protection rules → выбрать ветку `main` → поставить галочку "Require status checks to pass before merging" → выбрать job `Java CI Pipeline / test`.

### 5. Всегда ли нужно 100% покрытие тестами?
Нет. Оптимальный промышленный стандарт — 80-90%. В нашем проекте настроен порог 80% через JaCoCo в `pom.xml`.

### 6. Какой стек технологий используется?
- Язык: Java 8
- Фреймворк тестирования: JUnit 5
- Измерение покрытия: JaCoCo Maven Plugin
- Сборка: Apache Maven
- CI: GitHub Actions (YAML)
